Feedback & Programme Directory Page

Technical Description

The Feedback and Programme Directory page is structured into three distinct sections: a scrollable programme directory, a ratings and reviews panel, and a feedback form. The page links to the shared style.css external stylesheet for consistent typography, colours, and layout across the site.

The programme directory uses display: grid with grid-template-columns: repeat(3, 1fr) to arrange six programme cards into two rows of three columns. The wrapper div uses max-height: 500px and overflow-y: auto to create a scrollable container. Each card uses transition: transform 0.2s for a smooth lift effect on hover.

The feedback form uses two <fieldset> elements with <legend> tags to group related fields into "Personal Details" and "Feedback Details". It includes all required input types: type="text", type="email", type="tel", type="date", type="datetime-local", a <textarea>, a <select> dropdown, a multiple select list, and a <datalist> for searchable suggestions. JavaScript provides three interactive features: a live character counter that updates on every keystroke using an input event listener, field validation on form submission with error messages displayed next to invalid fields, and a confirmation message shown on successful submission without a page reload.

Accessibility

All images include descriptive alt text. Every form input has an associated <label> linked via the for attribute. Required fields are marked with a visible asterisk and the required HTML attribute. The sort dropdown uses aria-label. Error messages are placed directly below their fields and the confirmation message uses role="alert" so assistive technologies announce it automatically.

Team Page

Technical Description

The Team page presents four team member cards in a responsive grid using display: grid with grid-template-columns: repeat(auto-fill, minmax(210px, 1fr)), which automatically wraps cards onto a new row on smaller screens. Each card contains three child elements: .member-photo for the thumbnail image, .member-info showing the name and role at all times, and .overlay for the expandable details panel.

The expandable details effect is implemented using CSS only — no JavaScript is required. The .overlay has max-height: 0 and overflow: hidden by default. On :hover or :focus, the rule .member-card:hover .overlay sets max-height: 200px and restores padding, causing the panel to expand downward. A transition on max-height and padding creates the smooth sliding animation.

Accessibility

Each card has tabindex="0" for keyboard navigation and role="button" with an aria-label identifying the team member. All images include descriptive alt text. The focus state reuses the hover styling — a green outline: 3px solid #4ddb85 — providing a clear visible indicator for keyboard users.

Content Page — Challenges of Urbanisation

Technical Description

The content page covers the Challenges of Urbanisation in relation to SDG 11. It is divided into four clearly defined sections, each with a unique id attribute to support internal anchor navigation. At the top, an internal navigation menu uses an ordered list with anchor links (href="#section-id") so users can jump directly to any section. Each section heading uses scroll-margin-top: 20px to prevent the sticky header from overlapping the section target.

Images use border-radius: 10px, box-shadow, and fixed height with object-fit: cover for consistent presentation. A three-column image row uses display: grid; grid-template-columns: 1fr 1fr 1fr, collapsing to one column on small screens via a @media query. The Go to Top button uses position: fixed; bottom: 30px; right: 30px so it is always visible while scrolling, and links to id="top" on the header element.

Accessibility

The page follows a strict heading hierarchy: one <h1> in the banner, <h2> for each section, and <h3> for sub-topics. All images include meaningful alt text. The internal navigation uses aria-label="Page contents" to distinguish it from the main site navigation. The Go to Top button includes aria-label="Go back to the top of the page" for screen reader users.

Challenges and Lessons Learned

One of the main challenges I faced was a JavaScript variable name mismatch in the feedback form. The character counter variables (messageArea, charCounter, MAX_CHARS) did not match the names used in the event listener (messageBox, counter, MAX), which caused a ReferenceError that broke the entire script. I resolved this by carefully reviewing all variable names and making them consistent throughout. This taught me to always declare variables in one place and reference them by the same name.

A second challenge was implementing the team card hover effect correctly. My first approach used an absolutely positioned overlay on the photo, which did not match the brief's requirement for the details to appear below the card. I reworked the design using max-height: 0 and a CSS transition on the details box placed after the name bar, producing the correct slide-down behaviour using CSS only. This taught me to read requirements carefully before coding.

I also found it challenging to keep the content page consistent with the rest of the site. Initially it had all its CSS embedded instead of linking to style.css, which caused header and footer styling inconsistencies. Moving page-specific styles to an embedded block and using the shared stylesheet for global styles resolved this.
